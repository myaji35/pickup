# Feature Specification: 기관 차량 및 승객명단 관리

**Feature Branch**: `001-fleet-roster-management`
**Created**: 2025-11-18
**Status**: Draft
**Input**: User description: "기관관리자가 운행차량 및 효과적인 승객명단을 관리하는 기능"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 차량 등록 및 관리 (Priority: P1)

기관 관리자는 자신의 기관에서 운행할 차량을 등록하고, 차량 정보를 조회/수정/삭제할 수 있어야 한다. 차량은 차량 번호 뒤 4자리로 식별되며, 최대 승객 수용 인원(5-15인승)을 반드시 지정해야 한다.

**Why this priority**: 차량 정보는 승객 배정 및 경로 최적화의 기초 데이터이다. 차량이 없으면 서비스 자체가 불가능하므로 최우선 기능이다.

**Independent Test**: 관리자가 로그인 후 차량 등록 화면에서 차량번호(뒤 4자리)와 승객 정원을 입력하여 차량을 등록하고, 등록된 차량 목록을 조회할 수 있으면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 기관 관리자가 로그인한 상태, **When** 차량 등록 화면에서 차량번호 뒤 4자리 "1234"와 승객 정원 "12명"을 입력하고 등록 버튼을 클릭, **Then** "차량이 성공적으로 등록되었습니다" 메시지가 표시되고 차량 목록에 해당 차량이 나타난다.
2. **Given** 차량 "1234"가 이미 등록된 상태, **When** 동일한 차량번호 "1234"로 다시 등록 시도, **Then** "이미 등록된 차량번호입니다" 오류 메시지가 표시되고 등록이 거부된다.
3. **Given** 차량 목록에 3대의 차량이 등록된 상태, **When** 차량 목록 조회, **Then** 3대의 차량이 차량번호, 승객 정원, 등록일시와 함께 목록으로 표시된다.
4. **Given** 차량 "1234"가 등록된 상태, **When** 해당 차량의 승객 정원을 12명에서 15명으로 수정, **Then** "차량 정보가 수정되었습니다" 메시지가 표시되고 차량 목록에서 정원이 15명으로 업데이트된다.
5. **Given** 차량 "1234"가 등록되어 있지만 현재 배정된 승객이 없는 상태, **When** 해당 차량 삭제 버튼 클릭, **Then** "차량이 삭제되었습니다" 메시지가 표시되고 차량 목록에서 제거된다.

### User Story 2 - 승객 명단 수동 입력 관리 (Priority: P2)

기관 관리자는 웹 UI를 통해 승객을 한 명씩 수동으로 추가하고, 각 승객의 이름, 연락처, 탑승지/하차지 주소, 셔틀 유형(아침/저녁/임시)을 입력할 수 있어야 한다.

**Why this priority**: 엑셀 업로드 기능이 없어도 소규모 기관에서는 수동 입력으로 서비스를 시작할 수 있다. MVP 단계에서 핵심 가치를 검증할 수 있다.

**Independent Test**: 관리자가 승객 추가 화면에서 승객 정보를 입력하고 저장한 후, 승객 목록에서 해당 승객을 조회/수정/삭제할 수 있으면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 기관 관리자가 로그인한 상태, **When** 승객 추가 화면에서 이름 "김철수", 연락처 "010-1234-5678", 탑승지 "서울시 강남구 테헤란로 123", 하차지 "서울시 중구 세종대로 110", 셔틀 유형 "아침"을 입력하고 저장, **Then** "승객이 추가되었습니다" 메시지가 표시되고 승객 목록에 해당 승객이 나타난다.
2. **Given** 승객 "김철수"가 등록된 상태, **When** 승객 목록에서 "김철수"의 연락처를 "010-9999-8888"로 수정, **Then** "승객 정보가 수정되었습니다" 메시지가 표시되고 승객 상세정보에서 연락처가 업데이트된다.
3. **Given** 승객 "김철수"가 등록된 상태, **When** 해당 승객의 삭제 버튼 클릭, **Then** "승객을 삭제하시겠습니까?" 확인 메시지가 표시되고, 확인 시 승객이 목록에서 제거된다.

### User Story 3 - 승객 명단 엑셀 일괄 업로드 (Priority: P3)

기관 관리자는 정해진 엑셀 템플릿 형식에 따라 승객 정보를 작성한 파일을 업로드하여, 여러 승객을 한 번에 등록할 수 있어야 한다.

**Why this priority**: 대규모 기관(수십 명 이상 승객)에서는 수동 입력이 비효율적이므로 일괄 업로드 기능이 필수적이다. 하지만 소규모 기관에서는 수동 입력만으로도 서비스 가능하므로 우선순위가 상대적으로 낮다.

**Independent Test**: 관리자가 엑셀 템플릿을 다운로드하고, 승객 정보를 입력한 후 업로드하여 승객 목록에 일괄 추가되는지 확인하면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 기관 관리자가 로그인한 상태, **When** "엑셀 템플릿 다운로드" 버튼 클릭, **Then** 필수 컬럼(이름, 연락처, 탑승지 주소, 하차지 주소, 셔틀 유형)이 정의된 엑셀 파일이 다운로드된다.
2. **Given** 엑셀 템플릿에 10명의 승객 정보가 올바르게 입력된 상태, **When** 해당 파일을 업로드, **Then** "10명의 승객이 성공적으로 등록되었습니다" 메시지가 표시되고 승객 목록에 10명이 추가된다.
3. **Given** 엑셀 파일에 필수 컬럼(이름)이 누락된 행이 포함된 상태, **When** 해당 파일을 업로드, **Then** "2번째 행: 이름이 누락되었습니다" 등의 상세 오류 메시지가 표시되고, 오류가 없는 행만 선택적으로 등록할지 물어본다.
4. **Given** 엑셀 파일에 이미 등록된 연락처와 중복되는 승객이 포함된 상태, **When** 해당 파일을 업로드, **Then** "3번째 행: 이미 등록된 연락처입니다 (010-1234-5678)" 경고 메시지가 표시되고, 중복 행을 건너뛸지 덮어쓸지 선택할 수 있다.

### User Story 4 - 승객 그룹 생성 및 관리 (Priority: P1)

기관 관리자는 승객 그룹을 생성하고, 각 그룹에 고유한 그룹 코드와 그룹명을 부여할 수 있어야 한다. 등록된 승객들을 특정 그룹에 할당하거나 해제할 수 있어야 한다.

**Why this priority**: 승객 그룹은 차량과 승객을 연결하는 핵심 구조이며, 차량 교체 시나리오에서 승객 재배정을 효율적으로 처리할 수 있게 해준다. P1 기능인 차량 관리와 함께 필수적이다.

**Independent Test**: 관리자가 그룹 "A01-아침노선"을 생성하고, 승객 3명을 해당 그룹에 할당한 후, 그룹 상세정보에서 할당된 승객 목록을 조회할 수 있으면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 기관 관리자가 로그인한 상태, **When** 승객 그룹 생성 화면에서 그룹 코드 "A01", 그룹명 "아침노선 A그룹"을 입력하고 생성, **Then** "승객 그룹이 생성되었습니다" 메시지가 표시되고 그룹 목록에 해당 그룹이 나타난다.
2. **Given** 그룹 "A01"이 생성되고 승객 "김철수", "이영희", "박민수"가 등록된 상태, **When** 3명의 승객을 그룹 "A01"에 할당, **Then** "3명의 승객이 그룹에 할당되었습니다" 메시지가 표시되고, 그룹 상세정보에서 할당된 승객 목록(총 3명)이 조회된다.
3. **Given** 그룹 "A01"에 승객 "김철수"가 할당된 상태, **When** "김철수"의 그룹 할당을 해제, **Then** "그룹 할당이 해제되었습니다" 메시지가 표시되고, 그룹의 할당 승객 목록에서 "김철수"가 제거된다.
4. **Given** 그룹 "A01"이 생성된 상태, **When** 동일한 그룹 코드 "A01"로 다시 생성 시도, **Then** "이미 존재하는 그룹 코드입니다" 오류 메시지가 표시되고 생성이 거부된다.

### User Story 5 - 차량-그룹 연결 및 차량 교체 (Priority: P2)

기관 관리자는 차량 등록 시 승객 그룹을 선택하여 연결할 수 있어야 한다. 차량 삭제 후 신규 차량 등록 시 기존 그룹 코드를 선택하여 연결하면, 해당 그룹의 모든 승객이 자동으로 신규 차량에 배정되어야 한다.

**Why this priority**: 차량 고장, 정비, 교체 등의 상황에서 승객을 일일이 재배정하지 않고 그룹 단위로 신속하게 차량을 교체할 수 있다. 운영 효율성을 크게 향상시키는 기능이다.

**Independent Test**: 관리자가 차량 "1234"를 그룹 "A01"과 연결한 후, 차량 "1234"를 삭제하고 신규 차량 "5678"을 등록하면서 그룹 "A01"을 선택하면, 그룹 "A01"의 모든 승객이 차량 "5678"에 자동 배정되는지 확인하면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 차량 "1234"(정원 12명)와 그룹 "A01"(승객 10명)이 등록된 상태, **When** 차량 등록 화면에서 그룹 "A01"을 선택하여 차량 "1234"에 연결, **Then** "차량과 그룹이 연결되었습니다" 메시지가 표시되고, 차량 상세정보에서 연결된 그룹 "A01"과 승객 10명이 조회된다.
2. **Given** 차량 "1234"가 그룹 "A01"(승객 15명)과 연결하려는 상태이며 차량 정원이 12명, **When** 그룹 "A01"을 차량 "1234"에 연결 시도, **Then** "그룹 승객 수(15명)가 차량 정원(12명)을 초과합니다" 오류 메시지가 표시되고 연결이 거부된다.
3. **Given** 차량 "1234"가 그룹 "A01"과 연결된 상태, **When** 차량 "1234" 삭제, **Then** "차량이 삭제되었습니다" 메시지가 표시되고, 그룹 "A01"과 그룹의 승객들은 유지되며 미배정 상태로 전환된다.
4. **Given** 그룹 "A01"(승객 10명)이 미배정 상태로 존재, **When** 신규 차량 "5678"(정원 12명)을 등록하면서 그룹 "A01" 선택, **Then** "차량이 등록되고 그룹이 연결되었습니다" 메시지가 표시되고, 차량 "5678" 상세정보에서 그룹 "A01"의 승객 10명이 자동으로 배정된 것을 확인할 수 있다.

### User Story 6 - 승객 및 차량 통합 검색/필터링 (Priority: P3)

기관 관리자는 승객 이름, 연락처, 차량번호, 그룹 코드 등으로 검색하고, 셔틀 유형(아침/저녁/임시), 배정 상태(배정됨/미배정), 그룹 할당 상태 등으로 필터링할 수 있어야 한다.

**Why this priority**: 승객/차량/그룹 수가 많아지면 검색/필터 기능이 유용하지만, 소규모 기관에서는 전체 목록 조회만으로도 충분하므로 우선순위가 낮다.

**Independent Test**: 관리자가 승객 목록에서 이름 "김철수"로 검색하면 해당 승객만 표시되고, "아침" 셔틀 유형으로 필터링하면 아침 셔틀 승객만 표시되며, 그룹 "A01"로 필터링하면 해당 그룹 승객만 표시되는지 확인하면 테스트 완료.

**Acceptance Scenarios**:

1. **Given** 승객 목록에 "김철수", "이영희", "박민수"가 등록된 상태, **When** 검색창에 "김철수" 입력, **Then** "김철수"만 검색 결과로 표시된다.
2. **Given** 승객 목록에 아침 셔틀 5명, 저녁 셔틀 3명이 등록된 상태, **When** "아침" 셔틀 유형 필터 선택, **Then** 아침 셔틀 승객 5명만 목록에 표시된다.
3. **Given** 승객 10명 중 7명이 그룹에 할당되고 3명은 미할당 상태, **When** "미할당" 필터 선택, **Then** 미할당 승객 3명만 목록에 표시된다.
4. **Given** 그룹 "A01", "B01", "C01"에 각각 승객들이 할당된 상태, **When** 그룹 코드 "A01"로 검색, **Then** 그룹 "A01"에 속한 승객만 목록에 표시된다.

### Edge Cases

**차량 관리 관련**:
- 차량 정원을 초과하는 그룹이 연결된 상태에서 차량 정원을 축소하려고 하면 어떻게 처리할 것인가? (예: 15명 그룹 연결 후 정원을 12명으로 변경)
- 차량에 그룹이 연결된 상태에서 해당 차량을 삭제하려고 하면 어떻게 처리할 것인가? → 그룹과 승객은 유지되며 미배정 상태로 전환됨 (명세에 명시됨)

**승객 그룹 관련**:
- 승객이 이미 그룹 A에 할당된 상태에서 그룹 B에도 할당하려고 하면 어떻게 처리할 것인가? → 하나의 승객은 하나의 그룹에만 속할 수 있음 (FR-025)
- 그룹을 삭제하려고 할 때, 해당 그룹에 승객이 할당되어 있거나 차량과 연결되어 있으면 어떻게 처리할 것인가?
- 그룹에 할당된 승객을 삭제하면 그룹의 총 승객 수가 자동으로 업데이트되어야 하는가?
- 엑셀 업로드로 승객을 일괄 등록할 때 그룹 할당도 동시에 할 수 있는가? (템플릿에 그룹 코드 컬럼 포함 여부)

**승객 관리 관련**:
- 승객이 이미 그룹에 할당된 상태에서 해당 승객을 삭제하려고 하면 어떻게 처리할 것인가? → 그룹 할당이 자동 해제됨 (FR-030)
- 엑셀 업로드 시 파일 크기가 매우 크거나(수천 행), 형식이 완전히 잘못된 경우 어떻게 처리할 것인가? → 최대 1000행, 5MB 제한 (Assumptions에 명시됨)
- 동일한 연락처를 가진 승객이 여러 명 등록되어 있는 경우 어떻게 구분할 것인가? → 연락처는 기관 내 고유 식별자로 중복 불가 (Assumptions에 명시됨)
- 승객의 탑승지/하차지 주소가 유효하지 않거나 형식이 잘못된 경우 어떻게 검증할 것인가? → 텍스트로 입력받으며 이 기능에서는 검증하지 않음 (Assumptions에 명시됨)

## Requirements *(mandatory)*

### Functional Requirements

**차량 관리 요구사항**:

- **FR-001**: 시스템은 기관 관리자가 차량을 등록할 수 있어야 하며, 차량번호 뒤 4자리와 승객 정원(5-15명)을 필수 입력값으로 받아야 한다.
- **FR-002**: 시스템은 동일한 차량번호(뒤 4자리)의 중복 등록을 방지해야 한다.
- **FR-003**: 시스템은 기관 관리자가 등록된 차량 목록을 조회할 수 있어야 하며, 차량번호, 승객 정원, 등록일시를 표시해야 한다.
- **FR-004**: 시스템은 기관 관리자가 차량 정보(승객 정원)를 수정할 수 있어야 한다.
- **FR-005**: 시스템은 기관 관리자가 차량을 삭제할 수 있어야 하며, 삭제 시 해당 차량에 배정된 승객이 있는 경우 경고 메시지를 표시하고 확인을 요구해야 한다.

**승객 명단 관리 요구사항**:

- **FR-006**: 시스템은 기관 관리자가 승객을 수동으로 추가할 수 있어야 하며, 이름, 연락처, 탑승지 주소, 하차지 주소, 셔틀 유형(아침/저녁/임시)을 필수 입력값으로 받아야 한다.
- **FR-007**: 시스템은 연락처 형식을 검증해야 하며, 올바른 휴대폰 번호 형식(010-XXXX-XXXX)만 허용해야 한다.
- **FR-008**: 시스템은 기관 관리자가 등록된 승객 목록을 조회할 수 있어야 하며, 이름, 연락처, 셔틀 유형, 배정 차량, 등록일시를 표시해야 한다.
- **FR-009**: 시스템은 기관 관리자가 승객 정보를 수정할 수 있어야 한다.
- **FR-010**: 시스템은 기관 관리자가 승객을 삭제할 수 있어야 하며, 삭제 시 확인 메시지를 표시해야 한다.

**엑셀 일괄 업로드 요구사항**:

- **FR-011**: 시스템은 기관 관리자가 승객 명단 엑셀 템플릿을 다운로드할 수 있어야 하며, 템플릿에는 이름, 연락처, 탑승지 주소, 하차지 주소, 셔틀 유형 컬럼이 포함되어야 한다.
- **FR-012**: 시스템은 기관 관리자가 엑셀 파일(.xlsx 형식)을 업로드하여 여러 승객을 일괄 등록할 수 있어야 한다.
- **FR-013**: 시스템은 엑셀 업로드 시 각 행의 데이터를 검증해야 하며, 필수 컬럼 누락, 형식 오류 등이 있는 경우 상세한 오류 메시지(행 번호 포함)를 표시해야 한다.
- **FR-014**: 시스템은 엑셀 업로드 시 중복된 연락처가 발견되면 경고 메시지를 표시하고, 건너뛰기 또는 덮어쓰기 옵션을 제공해야 한다.
- **FR-015**: 시스템은 엑셀 업로드 결과를 요약하여 표시해야 한다(성공 N명, 실패 M명, 중복 K명).

**승객-차량 배정 요구사항**:

- **FR-016**: 시스템은 기관 관리자가 승객을 특정 차량에 배정할 수 있어야 한다.
- **FR-017**: 시스템은 차량의 승객 정원을 초과하여 배정할 수 없도록 제한해야 하며, 초과 시 오류 메시지를 표시해야 한다.
- **FR-018**: 시스템은 기관 관리자가 승객의 차량 배정을 해제할 수 있어야 한다.
- **FR-019**: 시스템은 차량 상세정보에서 해당 차량에 배정된 승객 목록을 조회할 수 있어야 하며, 현재 배정 인원/정원을 표시해야 한다.

**검색 및 필터링 요구사항**:

- **FR-020**: 시스템은 기관 관리자가 승객 이름, 연락처로 검색할 수 있어야 하며, 부분 일치 검색을 지원해야 한다.
- **FR-021**: 시스템은 기관 관리자가 차량번호로 검색할 수 있어야 한다.
- **FR-022**: 시스템은 승객 목록을 셔틀 유형(아침/저녁/임시)으로 필터링할 수 있어야 한다.
- **FR-023**: 시스템은 승객 목록을 배정 상태(배정됨/미배정)로 필터링할 수 있어야 한다.

**승객 그룹 관리 요구사항**:

- **FR-024**: 시스템은 승객 그룹을 생성할 수 있어야 하며, 각 그룹은 고유한 그룹 코드를 가져야 한다.
- **FR-025**: 시스템은 승객을 특정 그룹에 할당할 수 있어야 하며, 하나의 승객은 하나의 그룹에만 속할 수 있다.
- **FR-026**: 시스템은 차량 등록 시 승객 그룹 코드를 선택하여 연결할 수 있어야 한다.
- **FR-027**: 시스템은 차량 삭제 시, 해당 차량에 연결된 승객 그룹을 유지해야 하며, 그룹에 속한 승객들의 정보는 보존되어야 한다.
- **FR-028**: 시스템은 신규 차량 등록 시 기존 승객 그룹 코드를 선택하여 연결할 수 있어야 하며, 연결 시 해당 그룹의 모든 승객이 자동으로 신규 차량에 배정되어야 한다.

**데이터 무결성 및 검증 요구사항**:

- **FR-029**: 시스템은 차량 정원 변경 시, 현재 배정된 승객 수가 새 정원을 초과하는 경우 경고 메시지를 표시하고 변경을 거부해야 한다.
- **FR-030**: 시스템은 승객 삭제 시, 해당 승객의 차량 배정 및 그룹 할당을 자동으로 해제해야 한다.
- **FR-031**: 시스템은 승객 그룹을 차량에 연결할 때, 그룹의 총 승객 수가 차량 정원을 초과하는 경우 경고 메시지를 표시하고 연결을 거부해야 한다.

### Key Entities

- **차량 (Vehicle)**: 기관이 운행하는 셔틀 차량을 나타낸다. 주요 속성: 차량번호 뒤 4자리(고유 식별자), 승객 정원(5-15명), 연결된 승객 그룹 코드, 등록일시, 소속 기관.
- **승객 (Passenger)**: 셔틀 서비스를 이용하는 승객을 나타낸다. 주요 속성: 이름, 연락처(고유 식별자), 탑승지 주소, 하차지 주소, 셔틀 유형(아침/저녁/임시), 소속 그룹 코드, 등록일시, 소속 기관.
- **승객 그룹 (Passenger Group)**: 함께 동일한 차량을 이용하는 승객들의 논리적 묶음을 나타낸다. 주요 속성: 그룹 코드(고유 식별자), 그룹명, 총 승객 수, 생성일시, 소속 기관. 차량이 교체되어도 그룹은 유지되어 신규 차량에 재연결할 수 있다.
- **차량-그룹 연결 (Vehicle-Group Connection)**: 특정 차량과 승객 그룹 간의 연결 관계를 나타낸다. 주요 속성: 차량 ID, 그룹 코드, 연결일시. 하나의 차량은 하나의 그룹에만 연결될 수 있다.
- **기관 (Institution)**: B2B 서비스의 고객 기관을 나타낸다. 주요 속성: 사업자등록번호(고유 식별자), 기관명, 계약 정보. (이 기능에서는 간접적으로 참조되지만 상세 관리는 별도 기능)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기관 관리자가 차량 1대를 등록하는 데 1분 이내 소요된다.
- **SC-002**: 기관 관리자가 승객 그룹 1개를 생성하는 데 30초 이내 소요된다.
- **SC-003**: 기관 관리자가 승객 1명을 수동으로 추가하는 데 2분 이내 소요된다.
- **SC-004**: 기관 관리자가 엑셀로 50명의 승객을 업로드하는 데 5분 이내 소요된다(파일 준비 시간 제외, 업로드 및 검증 시간만).
- **SC-005**: 기관 관리자가 승객 10명을 그룹에 할당하는 데 2분 이내 소요된다.
- **SC-006**: 차량 삭제 후 신규 차량에 기존 그룹을 연결하는 데 1분 이내 소요되며, 그룹의 모든 승객이 자동으로 배정된다.
- **SC-007**: 승객 100명, 차량 10대, 그룹 5개가 등록된 상태에서 승객 목록 조회가 3초 이내에 완료된다.
- **SC-008**: 엑셀 업로드 시 데이터 검증 오류가 발생하면, 오류가 발생한 정확한 행 번호와 오류 사유를 표시한다.
- **SC-009**: 그룹의 총 승객 수가 차량 정원을 초과하여 연결 시도 시, 즉시 오류 메시지가 표시되어 잘못된 연결을 방지한다.
- **SC-010**: 관리자가 승객/차량/그룹 검색 기능을 사용하여 원하는 정보를 찾는 데 평균 30초 이내 소요된다.
- **SC-011**: 승객 명단 관리 기능 사용 후, 관리자의 90% 이상이 "직관적이고 사용하기 쉽다"고 평가한다.
- **SC-012**: 엑셀 업로드 기능 도입 후, 대규모 기관(50명 이상)의 승객 등록 시간이 수동 입력 대비 80% 이상 단축된다.
- **SC-013**: 승객 그룹 기반 차량 교체 기능 도입 후, 차량 교체 시 승객 재배정 시간이 개별 배정 방식 대비 95% 이상 단축된다.

## Assumptions

- 기관 관리자는 이미 시스템에 로그인되어 있으며, 자신이 소속된 기관의 데이터만 조회/관리할 수 있다. (인증/인가 기능은 별도 기능에서 구현)
- 차량번호 뒤 4자리는 동일 기관 내에서 고유하다고 가정한다. (실제로는 다른 기관과 중복 가능하지만, 기관별로 분리 관리됨)
- 승객의 연락처는 동일 기관 내에서 고유하다고 가정한다. (동일인이 중복 등록되지 않음)
- 승객 그룹 코드는 동일 기관 내에서 고유하다고 가정한다.
- 하나의 차량은 최대 하나의 승객 그룹과만 연결될 수 있다.
- 하나의 승객은 최대 하나의 그룹에만 속할 수 있다.
- 차량 삭제 시 연결된 승객 그룹과 그룹 내 승객들은 유지되며, 신규 차량 등록 시 재연결할 수 있다.
- 탑승지/하차지 주소는 텍스트로 입력받으며, 지오코딩 등의 주소 검증은 이 기능 범위에 포함되지 않는다. (추후 경로 최적화 기능에서 처리)
- 엑셀 파일은 .xlsx 형식만 지원한다. (구버전 .xls는 지원하지 않음)
- 엑셀 업로드 시 최대 파일 크기는 5MB, 최대 행 수는 1000행으로 제한한다.
- 승객의 셔틀 유형은 아침/저녁/임시 중 하나만 선택할 수 있다. (복수 선택 불가)

## Scope Boundaries

**포함되는 것 (In Scope)**:
- 차량 CRUD (등록, 조회, 수정, 삭제)
- 승객 CRUD (수동 입력 및 엑셀 업로드)
- 승객 그룹 CRUD (생성, 조회, 수정, 삭제)
- 승객-그룹 할당 관리
- 차량-그룹 연결 관리
- 차량 교체 시나리오 (삭제 후 신규 등록 시 그룹 재연결)
- 승객/차량/그룹 검색 및 필터링
- 엑셀 템플릿 다운로드 및 업로드 검증

**포함되지 않는 것 (Out of Scope)**:
- AI 기반 경로 최적화 및 탑승 순서 생성 (별도 기능)
- 실시간 차량 위치 추적 (별도 기능)
- 운전자 배정 및 관리 (별도 기능)
- 승객 앱 연동 (별도 기능)
- 주소 자동완성 및 지오코딩 (추후 기능)
- 승객 출결 관리 및 탑승/하차 체크 (별도 기능)
- 요금 정산 및 계약 관리 (별도 기능)
- **주간보호기관 8시간 케어 규칙 및 스케줄 검증** (별도 기능 002번으로 분리 예정)

## Dependencies

- 기관 인증/인가 시스템: 관리자가 자신의 기관 데이터만 접근하도록 제어하기 위해 필요
- 파일 업로드 시스템: 엑셀 파일 업로드 및 파싱을 위한 백엔드 인프라 필요
